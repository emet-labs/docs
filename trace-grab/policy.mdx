---
title: "Policy configuration"
description: "Reveal, tokenize, or drop specific fields with tracegrab.yaml."
---

`tracegrab.yaml` narrows the default disposition (tokenize strings, pass everything else) on a
per-field basis. Zero configuration is a valid configuration — with no file at all, you get
the safe default.

## The four dispositions

| Disposition | Meaning |
| --- | --- |
| `reveal` | Pass the value verbatim — no tokenization. |
| `tokenize` | Replace the value with a `TOK_` token. Written in config only to narrow an over-broad `reveal`. |
| `drop` | Remove the field entirely, including its linkage. |
| `default` | No rule matched. The built-in disposition applies: pass-verbatim fields pass, string leaves tokenize, numbers/booleans/null pass. |

```yaml
reveal:
  - outputs.status
  - inputs.currency
drop:
  - inputs.patient_id     # remove entirely — even the linkage is sensitive
time: shift               # preserve all intervals, destroy absolute timestamps
```

## Path syntax

Policy entries use the same dotted paths printed in `report.md`:

- `.` separates object segments: `inputs.user.email`.
- `*` matches exactly one segment: `inputs.*.email` matches `inputs.user.email`, not
  `inputs.user.profile.email`.
- `**` matches zero or more segments: `inputs.**` matches `inputs` and every descendant.
- Array elements use a literal `[*]` suffix on their parent segment: `inputs.items[*].sku`.

There is no escaping syntax. A source key containing `.` or a wildcard token can't be targeted
unambiguously — copy the exact path from the generated report instead of guessing.

## How conflicting rules resolve

Given a concrete path, `trace-grab`:

1. Collects every rule (across `reveal`, `tokenize`, `drop`) whose pattern matches.
2. If none match, applies `default`.
3. Otherwise finds the **most specific** matching rule (literal segment count first, then
   total segment count — fewer wildcards wins).
4. If one rule is uniquely most specific, its disposition wins.
5. If multiple rules tie on specificity, the **most restrictive** disposition wins: `drop` >
   `tokenize` > `reveal`.

Failing closed is the only acceptable ambiguity resolution in a security config: when two
rules are equally specific, the one that removes more information wins.

### Worked example: narrow an over-broad reveal

```yaml
reveal:
  - inputs.**
tokenize:
  - inputs.auth.secret
```

Both rules match `inputs.auth.secret`, but the exact `tokenize` path is more specific than
`inputs.**`, so the secret is tokenized while other input strings remain revealed.

## Required fields can't be removed

Top-level record fields (`id`, `trace_id`, `parent_id`, `name`, `kind`, `start`, `end`,
`status`, `error.kind`, `error.message`, `source.vendor`) and structurally required fields
(`labels[*].key`, `labels[*].value`, `links[*].trace_id`, `links[*].span_id`) can't be dropped
from the record. For these, `drop` falls back to the next most restrictive option:

- **String fields** (`id`, `name`, `error.message`, ...): `drop` → `tokenize`.
- **Non-string fields** (e.g. a numeric `labels[*].value`): `drop` → `default` (pass).
- **`status`**: always passes — it's an enum, not free text.

`drop` on a key *inside* a bag (`inputs.user.email`, `unmapped.note`, ...) removes that key
from the output object normally — this fallback only applies to the required fields above.

## Unknown keys and unmatched rules

A typo'd top-level key in `tracegrab.yaml` (anything outside `version`, `reveal`, `tokenize`,
`drop`, `time`) is a hard error — the CLI exits non-zero and no corpus is written.

A rule that matches zero paths in the corpus is reported in `manifest.json`'s `warnings` array
and surfaced in `report.md`. This is the classic redaction failure: a rule written against a
half-remembered field name, silently matching nothing. Treat any unmatched-rule warning as a
configuration error to investigate.

## Time handling

```yaml
time: shift
```

Applies a single constant per-corpus offset — derived from your salt, so it's stable across
batches — to every `start`/`end` value. Ordering and every interval survive; absolute position
does not. The default, `time: absolute`, leaves timestamps untouched.
