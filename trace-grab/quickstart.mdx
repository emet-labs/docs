description: "Run your first grab and verify that a value never appears in plaintext."
---

In this tutorial, you sanitize a trace export. You then review the output and check that a sensitive value is not in it.

## Before you start

You need Node.js 20 or later. You do not install trace-grab. You run it with `npx`.

You also need a trace export on your disk. It can be a LangSmith export, an OTLP JSON file, or plain span-shaped JSONL.

## 1. Sanitize the export

Run `grab` with the path to your export and an output directory.

```sh
npx @emetlabs/trace-grab grab ./langsmith-export --out ./corpus --from langsmith
```

<Note>
The input in this example is a directory. When the input is a directory, you must add `--from langsmith`. Without it, `grab` stops with an error. For a single file, `--from` is optional. See the [CLI reference](/trace-grab/reference/cli).
</Note>

On the first run, trace-grab writes a secret salt to `.trace-grab/salt` (mode `0600`). It also prints a notice.

**Keep this file.** The salt keeps token assignment stable across batches. If you lose it, a second corpus does not correlate with the first. trace-grab shows no error in this case.

`grab` writes four files to the output directory:

| File | Contents |
| --- | --- |
| `corpus.jsonl` | One sanitized record on each line, in the [`trace-corpus-v1`](/trace-grab/reference/schema) shape. |
| `manifest.json` | Metadata for the corpus: schema version, generator, digest, and warnings. |
| `policy.yaml` | A copy of the policy that produced this bundle. If you gave no policy, this is the default policy. |
| `report.md` | The field paths that trace-grab saw and the action for each path. |

## 2. Review the report

Open `report.md` in the output directory. It lists every field path that trace-grab saw. For each path, it gives the action: tokenized, revealed, dropped, or passed by default.

Read this report before you send anything.

## 3. Check one value

Run `check` to look up the token for a value in the finished bundle. It also searches the bundle for the plaintext value.

```sh
npx @emetlabs/trace-grab check --value "alice@corp.com" ./corpus
```

If the value does not appear in plaintext, the output looks like this:

```txt
appears as TOK_88b0e13a5d in 14 records; never appears in plaintext
```
