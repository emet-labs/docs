---
title: "Corpus schema"
description: "The trace-corpus-v1 record shape."
---

`trace-corpus-v1` describes two sets of values that have one structure:

- **Generic JSONL input.** One `RawRecord` on each line, with the original strings of the vendor.
- **The output corpus.** One `CorpusRecord` on each line. It has the same structure as `RawRecord`. In a `CorpusRecord`, string values outside the pass-verbatim fields below are opaque tokens.

Sanitization is a pure function: `RawRecord -> CorpusRecord`. It processes one record at a time and keeps no state across records.

<Note>
`trace-grab` does not split a record into requested and completed events. It does not derive causal edge classes. It does not apply observation-time rules. One record is one source span, in the shape that the vendor gave it. Downstream analysis tools do this classification. This CLI does not.
</Note>

## Record shape

| Field | Type | Notes |
| --- | --- | --- |
| `id` | `string` | Unique within the corpus. |
| `trace_id` | `string` | Shared by every record in the same trace. |
| `parent_id` | `string \| null` | `null` for a root span. May reference an `id` absent from this corpus. |
| `name` | `string` | The tool, span, or run name, as the vendor gave it. |
| `kind` | `string` | The run or span type string of the vendor. It is not a fixed enum (`"llm"`, `"tool"`, `"chain"`, an OTLP span kind, ...). |
| `start` | `string` | ISO-8601, UTC. |
| `end` | `string \| null` | ISO-8601, UTC. `null` if the vendor recorded no end. |
| `status` | `"unset" \| "ok" \| "error"` | Normalized onto OTLP's three-value status model. |
| `error` | `{ kind: string; message: string } \| null` | `null` when `status != "error"` or when the vendor gave nothing. |
| `inputs` | JSON value | Nested JSON of any shape, in the vendor structure. trace-grab does not flatten it. |
| `outputs` | JSON value | Same shape rules as `inputs`. |
| `attributes` | `Record<string, JSON value>` | Structured vendor metadata that trace-grab recognizes. It uses the OTel style. |
| `labels` | `Label[]` | Native annotations only. |
| `links[]` | `Link[]` | An OTLP link object: `{ trace_id, span_id, attributes }`. The value is `[]` when the source has no link concept. |
| `unmapped` | `Record<string, JSON value>` | Source fields that the normalizer did not recognize. trace-grab keeps their shape unchanged. |
| `source` | `{ vendor: string }` | The parser that produced this record. Examples: `"langsmith"`, `"otlp"`. |

`Label` is `{ key: string; value: JSON value; comment: string | null }`. The fields `key` and `value` carry the annotation, for example `key: "correctness"` and `value: "correct"`. The field `comment` is free text that a person typed with the annotation.

## Default dispositions

This table shows the default `RawRecord -> CorpusRecord` mapping. It applies when you have no `tracegrab.yaml`. To change it for a field, see [Policy configuration](/trace-grab/policy).

| Field | Default | Why |
| --- | --- | --- |
| `id`, `trace_id`, `parent_id`, `links[].trace_id`, `links[].span_id` | Tokenized | These fields are strings, and this includes ids. Tokenization depends on the value and the salt. Equal ids give equal tokens. The topology stays. |
| `name`, `kind` | Pass verbatim | The vocabulary in which any candidate property is written. |
| `start`, `end`, numbers, booleans | Pass | Typed passthrough. These are not string values. |
| `status`, `error.kind` | Pass | A categorical signal. It is not prose. |
| `error.message` | Tokenized | Free text. |
| Object/array keys under `inputs`, `outputs`, `attributes`, `unmapped` | Pass | Keys are schema. They are not data. |
| Leaf string values under `inputs`, `outputs`, `attributes`, `unmapped` | Tokenized | The default string rule, applied to each leaf. trace-grab walks `unmapped` in the same way as `attributes`. |
| `labels[].key`, `labels[].value` | Pass verbatim | A categorical ground-truth signal (success, failure, or human intervention). If a vendor `value` holds prose and not a short label, use `drop: labels.value`. |
| `labels[].comment` | Tokenized | Free text that a person typed. |
| `source.vendor` | Pass verbatim | This is never partner content. The parser that ran sets it. The value comes from a closed set that the CLI controls. |

## Causality: copied, never derived

trace-grab copies `parent_id` and the optional `links[]` exactly as the source gave them. It infers nothing.

A `parent_id` can point to an `id` that is not in this corpus. These are the possible causes:

- The source export was partial.
- The time limit or the trace-count limit excluded the record.
- The vendor data is incomplete.

trace-grab keeps this condition. It does not repair it. The `dangling_parents` count in `manifest.json` makes the condition visible.

Tokenization depends on the value. It does not depend on the corpus. A token for a dangling `parent_id` is equal to the token of the record that it points to. This holds if that record exists under the same salt, also in a different batch.

## Timestamps

`start` and `end` are ISO-8601 strings in UTC. They have the sub-second precision that the vendor gave. LangSmith gives milliseconds. For OTLP, trace-grab converts unix nanoseconds.

The setting `time: shift` in `tracegrab.yaml` applies one constant offset to every `start` and `end` value. The offset comes from the salt and is the same for the whole corpus. Ordering and all intervals stay. Absolute position does not stay.

## Manifest

Each bundle has one `manifest.json`, next to `corpus.jsonl`. It holds metadata for the corpus. `grab` generates it. trace-grab does not copy it from partner content.

| Field | Type | Notes |
| --- | --- | --- |
| `schema_version` | `string` | `"trace-corpus-v1"`. |
| `generator` | `{ name: string; version: string }` | The tool and version that produced this bundle. |
| `generated_at` | `string` | ISO-8601 time when `grab` ran. |
| `source` | `{ vendor: string }` | The same vendor tag as the `source.vendor` of each record. |
| `warnings` | `string[]` | Unmatched policy rules and other notices that do not stop the run. |
